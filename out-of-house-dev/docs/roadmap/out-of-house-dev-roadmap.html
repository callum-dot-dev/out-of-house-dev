01 · Executive summary

One platform. Six revenue lines. Built to run itself.

The thesis of v3: every step of every line — from lead to live software, from enrolment to certificate — should be automated by default. Anything a human has to do twice gets a worker in the next sprint.

What we sell (in priority order)

  • AI automations — flagship, custom builds on the client's stack.
  • Websites & web apps — same-day sites, MVPs in weeks.
  • Internal software & AI growth engine — bespoke tools + lead pipelines.
  • Maintenance — continuous shipping retainer.
  • AI coaching — 1:1 at £100/hr + 3 / 6 / 12-week programmes for business and developers.
  • SaaS / AIaaS — LogoVault first; Prompt Locker, Inbox Fox, Fingerprint Fund queued.
  • Lead engine as a service — the same engine we use on ourselves, sold to clients.
  • AISEO — Generative-Engine Optimization for the era of AI search.

What's different in v3

  • The marketing site is the lead-magnet (free LogoVault tier, free AISEO audit, free 1:1 booking page).
  • Every paid product flows through one Stripe pipeline → one payments table → one webhook.
  • Every build runs through a multi-stage Claude orchestrator with persistent telemetry.
  • Every customer relationship sits in one Supabase schema; no second CRM.
  • Every manual step in this plan is marked red with a plan to automate it.

09 · AISEO programme

Be the brand AI recommends — durably.

The next wave of search is assistants picking answers, not users picking links. AISEO is how a brand stays referenced as models update.

Strategic position on grey-hat tactics

We do not do prompt-injection / hidden white-text "tricks". LLM providers already detect indirect prompt injection and increasingly penalise sites that use it. A single news cycle around a client "tricking" ChatGPT into recommending their brand would be brand-destroying. The durable play is to be genuinely cited, and that's the playbook we sell.

What an AISEO retainer ships, per month

Foundations

  • Organization + FAQ + Product schema across all key pages
  • llms.txt + AI-friendly information architecture
  • Explicit robots.txt allow for GPTBot, ClaudeBot, PerplexityBot
  • Heading + question-led copy rework

Authority

  • 5 citation placements per month (Reddit, Wikipedia, awesome-* lists, press)
  • 3 authority articles engineered to be the canonical source
  • Brand-mention coverage in industry comparisons
  • Adversarial defence: monitor competitor prompt-injection attempts

Measurement

  • 30 buyer-intent queries asked across 6 engines monthly
  • Brand-present / rank-position / cited-URL captured per query
  • Curve tracked over time, drift alerted in Slack
  • Quarterly business review with senior eng

Free entry tool

  • /aiseo runs a 14-axis audit on any domain in <5 seconds
  • Produces score + grade + prioritised fix list
  • Acts as lead magnet for paid programmes
  • Results stored in aiseo_audits for follow-up

10 · Claude Code orchestrator

From request → live deploy, with one senior eng at the steering wheel.

Every feature request, every project, every build runs through the same five-stage pipeline. Cost, tokens, status and review state are tracked per run in claude_runs.

Orchestrator pipeline

What's manual, what's not

StageWhoNotes
01 · ScopeClaude · sonnetAuto on request status = submitted.
02 · PlanClaude · opusRe-runs if scope is edited.
03 · Build promptClaude · opusProduces the brief for headless Claude Code.
04 · Claude Code workerWorkerRuns on Render/Fly with a clean worktree; commits + opens PR.
05 · ReviewSenior eng (human-in-loop)The only stage we deliberately keep manual — this is the quality gate.
06 · DeployClaude · haikuGenerates runbook; CI handles execution.
Roadmap to "lights-out" builds: by Q4 2026, low-risk requests (copy edits, schema-only changes, simple feature flag toggles) auto-merge after a passing eval + diff-classifier. High-risk requests stay in review. Target 60% of merges by auto-merge, 40% by senior review.

15 · Risk register

What could go wrong, and what we do about it.

If we don't name them, they get expensive. Each risk has a probability, impact, and the owner of the mitigation.

RiskPImpactMitigation
Outreach domain reputation damageMedHighUse a sub-domain (send.out-of-house.dev) + warm-up + strict daily caps. outreach-send already enforces this.
Stripe webhook drops a paymentLowHighIdempotency on payment_id in metadata; nightly reconciliation job to be added (planned Q2).
LLM cost runs awayMedMedPer-function token caps; nightly summary by model + run-type; alert at 80% of monthly budget.
Lead source TOS changeMedMedEach source is a row in lead_sources with a kill-switch; we can disable individual sources from the admin.
Single senior eng burnoutHighHighThe dev bench fills this gap. Course pipeline funnels candidates; trial-task gate vets them.
RLS misconfiguration leaks dataLowCatastrophicRLS is the foundation. Every migration ends with a check that every new table has enable row level security.
